## Plain summary (for David)

We took the smallest detector we could: one fixed ledger handle (#388) and one virtual loop, with the two routes wired into the loop. The question was whether anything in the geometry makes that wiring write a record. In this model, nothing does. The handle can give a turn that belongs to the detector and not to the incoming routes, which is clean. But a fixed turn closes the loop only for special incoming setups. It cannot give both a fixed −1 and a record. The graph closes up and leaves no new topology behind, so any record has to be a matter event next to the handle, and the geometry doesn't fix whether one happens. (Claude 026: for a charged particle it does. If the loop's current winds through the handle, Gauss's law changes the flux through it, which is already a #388 write; what is left open is which arc of the loop the current takes.) Geometry names the missing piece, a "write rule", without adopting it. There is also a question for you: does the exact-closure rule govern only the detector's own virtual loop, or also one loop through the routes? (Not both loops through the routes: if two loops close exactly at −1, the third is fixed at +1.) The handle doesn't settle that. (Answered at 10:48 AM: all loops; see the updates below.)

**Update (10:48 AM, §3a):** you ruled that within a world every loop must close exactly, the detector ones included, and only approximately in shadow space. That is neither Reading A nor B. Because the three loops' turns multiply, they cannot all close at −1: two at −1 force the third to +1. So the ruling works if "exact" for a loop means a fixed value, +1 or −1. **Geometry's answer (10:50 AM):** if "exact" means the frames line up (frame-level), the ruling works: with the detector's virtual loop at −1, exactly one route loop is −1 and the other +1, and which one is set by the routes or the spin structure in each world, not by the detector. If "exact" means every loop at −1 (the #424 spinor definition), there is no solution. **The question for you now: does "exact" mean frame-level?** Geometry is neutral.

**Update (11:17 AM, §3b):** you ruled that "exact" does not mean every loop picks up −1, and that a loop expected to pick up −1 must get exactly −1 within a world (approximate only in shadow space). Our reading (Creative Lead, not your words): a loop must get exactly the value expected of it. That rules out every loop at −1 and fits frame-level exactness, though it does not by itself pick it. With spin-½ adopted for fermions (§3c), and if exactness is frame-level (Creative Lead's reading, not adopted), then with the detector's virtual loop at −1 one route loop is at −1 and the other at +1, set in each world by the routes or the spin structure. What remains open is what fixes each loop's expected value; for the detector's virtual loop it is −1, and for the route loops it is forced by the product rule, not chosen. One option (our proposal, not adopted): the detector's virtual loop closes at −1, and the two route loops take the values that forces, say −1 and +1, named in advance; choosing that by hand would need its own justification.

**Update (11:24/11:26 AM, §3c):** you adopted spin-½ for fermions, with other spins deferred, and a hope that the model will suggest a natural generalization (11:26 AM; hope, not a ruling). With that, and if exactness is frame-level (Creative Lead's reading, not adopted; your 11:17 ruling fits it but does not adopt it), Geometry's pattern follows: the detector's virtual loop at −1, one route loop at −1 and the other at +1, set per world by the routes or the spin structure. If the routes carry a conserved charge, their line runs along one arc of that loop and nothing runs along the other, so it does not stay one, and its −1 is then open.

Hol(L) = Hol(C2)⁻¹·Hol(C1) up to conjugation, so the holonomies on any two cycles fix the third. For central values this holds exactly, with no conjugation caveat, and it fixes signs: if two cycles have spinor lift −𝟙, the third has lift (−𝟙)(−𝟙) = +𝟙 and so is not exact under the #424 definition, which asks for −𝟙 on every cycle (#428 §6a(c)3).
